# セキュリティ

[English](security.md) | **日本語** · [← README](../README.ja.md)

Collie は、ブラウザからサーバ上でコマンドを実行するためのツールです。ログインした人は誰でもそれができます。インターネットから HTTPS で使える前提で作られています（[セットアップ](setup.ja.md)）。このページでは、それが何に支えられているかを説明します。

## ログイン

- 最初のパスキーができたあとは、パスキーでしかログインできません。パスキーはフィッシングされません。そっくりな偽サイトでは使えないからです。
- それまでは、初期設定用のトークンでしかログインできません。tailnet や LAN の中にいることや、プロキシがリクエストに付けるヘッダでログインできることはありません。
- ログインの試行・招待リンクや復旧用リンク・初期設定用のトークンは、接続元のアドレスごとに回数を制限していて、失敗するほど待ち時間が延びます。失敗は接続元のアドレス付きで `auth: failed …` とログに残るので、fail2ban などに使えます。
- `--no-auth` はサーバ上での開発用です。ループバック以外のアドレスでは起動を拒否し、そのマシンから `localhost` 宛てに直接来たリクエストにしか応えません。プロキシ経由のものや、自分のドメイン名を `127.0.0.1` に向けた Web ページからのものは拒否します。

## もう一度パスキーが必要な変更

次の変更には、15 分以内のパスキーの確認が必要です（ログインも確認に数えます）。それより前なら、変更する前にパスキーを求めます。

- パスキーの追加・削除、別の端末を追加するリンクの発行
- 招待、復旧用リンクの発行、ユーザーの変更・削除
- 全体共通の skill・MCP・環境変数（全員のエージェントに効くもの）
- サーバ上の既存フォルダの登録と、プロジェクトのエージェントのホスト実行

そのため、盗まれたり開きっぱなしだったりしたセッションを使われても、これらを通じてあなたを締め出したり、あとから入り直せるようにしたり、自分のプロジェクトの外に手を伸ばしたりはできません。それ以外のことは、そのセッションをログアウトさせるまで、あなたと同じようにできてしまいます。

## ログイン中の端末

Account → **ログイン中の端末** に、端末ごとに最後に使われたアドレスが出ます。心当たりのないものはログアウトさせ、パスキーも確認してください。ログインは最後に使ってから 30 日間有効です。

招待リンクは 7 日間、端末追加・復旧用のリンクは 30 分間、使われるまでは持っている人なら誰でも使えます。不要になったものは Admin → Users で取り消してください。

## 誰に何が見えるか

- 権限のチェックはすべてサーバ側で行います。見る権限がないものは「存在しない」として扱われます。
- 管理者でも、ほかの人の個人プロジェクトや会話は見られません。

## エージェントが届く範囲

[セットアップ](setup.ja.md)の構成（専用ユーザー `collie` とファイアウォール）を前提にしています。

| | 隔離コンテナ（既定） | ホスト実行（管理者のみ） |
|---|---|---|
| ファイル | そのプロジェクトと worktree だけ | `collie` ユーザーが触れるものすべて（Collie 自身のデータも含む） |
| ネットワーク | インターネットには出られる。LAN・tailnet・このサーバ・Collie の API には届かない | `collie` ユーザーと同じファイアウォールのルール |
| あなた自身のアカウント（`~/.ssh` など） | 届かない | 届かない（`collie` は別のユーザーなので） |

- グループのプロジェクトは必ずコンテナで動きます。ホスト実行のエージェントを動かせるのは管理者だけです。
- メンバーは任意のフォルダを登録できません。clone は `https://` だけで、本人のコンテナの中で実行されます。
- プロジェクトのフォルダは入れ子にできないので、コンテナからほかのプロジェクトが見えることはありません。
- エージェントが Collie とやりとりできるのは、自分のコンテナに渡されたツール用ソケットだけです。プロジェクトのエージェントが指定できるのは、同じコンテナで動く本人のセッションだけです。
- SELinux が有効なシステム（Fedora、RHEL など）では、コンテナは SELinux のラベルなしで動きます。プロジェクトのファイルをホストと共有するためです。それ以外の壁（専用のユーザー名前空間、ケーパビリティなし、seccomp、自分のマウントだけ）はそのままです。

## 守られて*いない*もの

- コンテナ内のエージェントは、そのプロジェクトのファイルをすべて読めて、インターネットにも出られます。外に送られて困る秘密情報は、プロジェクトに置かないでください。
- ホスト実行のエージェントは、`collie` ユーザーの権限をすべて持ちます。
- Mac にはコンテナもファイアウォールもありません。エージェントはあなたとして動き、あなたのアカウントが届くものすべて（あなたのファイル、LAN、Collie 自身のデータ）に届きます。
- **コンテナの中でコンテナを動かせるようにする** をオンにしたプロジェクトでも、コンテナは `collie` ユーザーの ID のまま動き、見えるファイルとネットワークも変わりません。ただし、プロセスがコンテナ内の ID を切り替えられるようになり、カーネルの機能（FUSE、tun デバイス、独自の `/proc` やホスト名を持つ入れ子の名前空間）にも触れられるため、カーネルの不具合を突かれやすくなります。エージェントを信頼できるプロジェクトだけでオンにしてください。

## アップデート

- Collie がインストールするのは、Collie に組み込まれた鍵で署名を確かめられたリリースだけです。リリースのページのファイルを差し替えても、古いリリースを新しいものと偽っても、何もインストールされません。
- 署名付きのリリースを作れるのは、リリース用のワークフローを手動で実行できる人だけです（タグを push しても動きません）。エージェントが使う GitHub トークン（Collie の環境変数の `GH_TOKEN` など）には、**Actions**・**Workflows**・**Secrets** の権限を付けないでください。付いていると、エージェントがリリースを出したり、署名鍵を読み出したり、差し替えたりできてしまいます。
- 各リリースは、エージェント用イメージの土台（Ubuntu のパッケージ・Podman・mise）もダイジェストで固定しています。イメージのレジストリが別の土台を渡しても、サーバはそれを使いません。その上に入るエージェント（Claude Code・Codex・Playwright MCP サーバ）は、サーバでイメージをビルドするときに npm から入れます。
- アップデートを実行できるのは管理者だけです。Home エージェントからはできません。

## そのほか知っておくとよいこと

- エージェントが見せる HTML・SVG は、Collie 自身のページとしては決して動きません。ネットワークに出られないサンドボックスの中で開くので、**Run scripts** を押したあとでも、Collie のログイン状態に触れたり、外へ何かを送ったりはできません。
- Collie でプロジェクトを削除しても、ディスク上のファイルは消えません。消えるのは Collie が作った worktree だけで、そのブランチは残ります。

## 脆弱性の報告

公開の Issue ではなく、非公開で報告してください。方法は [SECURITY.md](../SECURITY.md) にあります。
